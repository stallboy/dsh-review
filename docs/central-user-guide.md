这份手册介绍当前的**中央 Web 模式**：你在浏览器中审核，接入的 DSH 节点负责实际审查、修复、门禁和提交。中央服务管理账号、项目与任务，不直接修改业务仓库。

独立中央日常使用需要管理员提供的**网址、账号和密码**，并确认项目已接入。也可以在 DSH“评审”标签内连接中央、选择项目并打开内嵌工作台。部署和节点配置见[部署说明](central-deployment.md)；未启用中央的原本地评审方式见[本地插件指南](dsh-code-review-guide.md)。

## 在 DSH 插件内使用中央

“评审”标签提供四个入口：

| 入口 | 用途 |
| --- | --- |
| 中央连接 | 选择本机托管或已有中央，编辑并应用连接，查看状态、停止或重试。 |
| 项目接入 | 核对名称、真实目录、VCS 和目标，手动接入或启停工作副本。 |
| 中央工作台 | 在插件内完成下文的项目查看、报告、候选审核和任务核对。 |
| 本地评审 | 仅尚未保存中央配置、且没有旧托管配置时显示，提供原本地评审。 |

### 启用连接

同一机器上使用少量项目时，可安装本机整合插件，选择“本机托管”，填写审核身份，点击“应用并启动”。普通插件包未包含中央服务时，本机启动按钮不可用；可改为“连接已有中央”，或由管理员安装整合包。包的选择与安装见[部署说明](central-deployment.md#11-同一机器上的插件内中央)。

连接已有中央时，填写中央地址、管理员提供的节点 ID 和 Token。「检查连接」逐项显示服务器可访问性、凭据验证和中央声明的注册兼容性。检查当前已保存的地址和节点时，可以留空 Token。检查其他地址时，请填写 Token 才能验证凭据。「保存并连接」才保存配置并注册节点。进入已有中央的工作台后，仍需使用中央用户账号登录。

启动时按钮显示“正在启动…”并阻止重复操作。成功后表单切换为“中央已连接”摘要，显示当前地址、审核身份和服务/节点状态；没有项目时优先引导“接入项目”，也可直接进入工作台。点击“修改连接”才编辑，未变化的就绪配置不能重复应用，“取消修改”保留当前运行连接。服务可访问但节点离线时会单独提示，等待节点恢复，不自动重启中央。

只选择模式、编辑文字或打开页面不会启动服务。已启用连接会在插件下次启动时自动恢复。点击「停止连接」可持久停用，之后用「启动已保存连接」恢复。关闭页面或切换会话不会停止中央。发生故障时，按页面提示核对地址、节点凭据或中央版本，需要排查时可以展开「诊断详情」并复制。点击「重试已保存连接」使用已保存配置，编辑中的草稿会保留在表单中。

本机审核身份与候选 owner 对应，首次初始化后不能通过连接表单静默切换为另一身份。中央已经保存配置时，即使当前连接停止，也应恢复中央后处理任务；“本地评审”不能用来绕过中央管理。

### 选择项目并开始审核

1. 等待中央服务就绪、节点在线，打开“项目接入”。
2. 核对每项候选的真实目录、VCS 和目标，点击“接入项目”。发现失败的候选会显示原因，需要先修正本地环境。
3. 当前会话的项目带有“当前项目”标识；接入后可点击“打开当前项目”直接进入中央项目页面。
4. 打开“中央工作台”，等待项目同步后，按下文发起审查或审核已有候选。

同一真实目录的多个会话共享接入记录；同名但不同目录的项目分别管理。接入不会自动发起审查。关闭会话不会取消接入；“停用项目”保留历史和工作目录，以后可以再次启用。

停用项目的目录暂时不可用，不会阻止其他项目恢复。中央页面重新启用后，节点会按原本地路径、VCS 和目标重新校验并准备执行资源，无需重启插件；目录已归档时应先恢复目录。节点初始化失败时，可在“项目接入”停用故障项目，但仍须确认旧实例已停止、没有未决任务及未确认事件。

有未决任务、未核验执行或未确认事件时，停用连接、更换中央和修改项目接入会被拒绝。先到原中央“任务记录”核对结果并处理恢复，不要通过删除配置或执行记录跳过它。

### 已有旧托管配置

尚未保存新连接时，原 `managed-node.json` 继续工作。插件提示“旧托管配置”时，不能直接用连接界面覆盖：先在原中央处理完旧任务，停用旧托管配置并重启插件，再设置新连接。旧执行记录、凭据和项目绑定不会自动迁移；需要管理员协助时，参照[部署说明](central-deployment.md)。

旧模式下，“中央工作台”保留“打开已有中央工作台”链接；顶部隐藏“本地评审”，不开放原本地写入。

本轮自动化测试覆盖隔离安装及中央进程启停，真实 DSH 宿主交互和 Windows、macOS、Linux 三平台仍待实际验收。

## 先认识五个名称

| 名称 | 可以怎样理解 |
| --- | --- |
| 项目 | 你要审查的一份业务代码，例如“服务器核心库”或“游戏客户端”。 |
| 执行节点 | 一台机器上运行的 DSH 插件实例，负责实际干活。一台物理机器可以有多个实例。 |
| 工作副本 | 节点上已经准备好的 Git 或 SVN 代码目录。项目接入时选择它。 |
| 审查报告 | 一次扫描的发现和说明。报告里的问题不一定都能立即生成修复。 |
| 候选 | 一份等待人审核的修复方案，包含说明、代码补丁、意见和版本记录。 |

点击审查、评论、修复或批准后，还会产生一条**任务记录**。它用来回答“操作有没有执行完”“结果是什么”“有没有交付到远端”。

常见流程如下：

**发起全量审查 → 查看报告和候选 → 提出意见或确认方案 → 必要时再次修复 → 人工批准 → 核对交付结果**

## 快速完成一次审核

以下假设管理员已经接入项目，且项目中已有候选。

### 第一步：登录并找到候选

1. 打开管理员提供的评审中心网址，输入账号和密码。
2. 在“工作台”的“需要关注”中点击候选标题；也可以进入“候选队列”。
3. 在队列中按“项目”“状态”筛选，或搜索标题、候选编号、负责人。

打开详情后，先核对**项目名称、候选标题、负责人和版本号**。`rev 1` 表示第一个补丁版本；修复后可能出现 `rev 2`、`rev 3`。

### 第二步：看方案，再看代码

按以下顺序阅读会比较容易：

1. **方案与证据**：问题是什么、为什么发生、准备怎样修、有什么验证依据。
2. **代码差异**：实际改了哪些文件和代码行，是否与方案一致。
3. **审核意见**：前面的意见是否已经得到回应。
4. **版本与门禁**：当前版本的来源，以及批准前会执行哪些检查命令。

代码差异默认展开全部文件。点击文件标题或用键盘 Enter/空格可单独折叠，顶部也提供“全部收起”和“全部展开”。同一候选、同一比较范围刷新或切换审核标签会保留状态；换候选、补丁版本或比较范围时重新展开。折叠不表示已审阅，不改变行内意见的文件、行号及左右侧定位。

“门禁”就是批准前必须执行的检查，例如编译、单元测试或项目自定义验证。它们会在执行节点上运行。

候选有问题时，先[提出意见](#提出意见与再次修复)。确认当前方案可以接受后，再继续批准。

### 第三步：确认人工判断和门禁

1. 如果“人工判断”中有项目，逐项阅读并确认。
2. 点击“批准并交付 →”。
3. 在弹窗中核对目标分支或 SVN 位置，以及**完整门禁命令**。
4. 勾选“我已核对，并同意节点执行以上门禁命令”。
5. 点击“确认批准并交付”。

人工判断用于记录需要人作决定的事项，例如是否接受兼容性变化。不能确认时，应先提出意见，不要为了启用按钮而勾选。

如果你不是候选负责人，写操作通常不可用。确实由你接手时，先与原负责人确认分工，再点击“接管候选”。接管会修改负责人并形成仓库记录。

### 第四步：到任务记录确认结果

批准后会进入“任务记录”。选择对应任务，查看业务结果、提交版本和执行日志。

**对一次成功的批准，通常需要同时看到“已提交”和“已交付远端”。仅看到“已结束”，还不能判断批准成功。**

Git 会向项目绑定的目标分支推送；SVN 会直接提交远端。这个入口会直接交付代码，不会替你创建合并请求。

## 六个页面分别做什么

| 页面 | 适合什么时候打开 |
| --- | --- |
| 工作台 | 每天开始工作时，先看待处理候选和项目同步状态。 |
| 项目管理 | 接入项目、打开项目详情、同步代码、开始全量审查，以及修改名称或启停项目。 |
| 审查报告 | 回看某次扫描的范围、发现和报告正文。 |
| 候选队列 | 筛选候选并进入具体审核。 |
| 任务记录 | 看执行进度、日志、业务结果、远端交付，以及请求取消或核验恢复。 |
| 执行节点 | 登记 DSH 节点、查看节点连接和工作副本，以及吊销节点凭据。 |

## 首次接入：管理员操作

如果你只是审核代码，可以跳过本节。这里的“管理员”和“审核人员”表示操作分工；**当前版本的账号权限一致**，尚未提供细粒度角色管理，但候选负责人的校验仍然有效。

### 1. 准备好服务和代码目录

管理员可按[一键部署与启动](oneclick-deployment.md)分别安装中央和 DSH 节点；先执行部署，再单独启动。中央首次部署会创建登录账号；节点首次仍需在 DSH 插件管理器启用输出路径中的插件。手工安装方式见[部署说明](central-deployment.md)。拆包后，源码安装入口是 `packages/dsh-plugin`，不再是仓库根目录。

执行节点需要能访问模型服务和业务仓库，并具备项目使用的构建工具。业务代码要提前下载到节点上，也就是先完成 Git clone 或 SVN checkout；Web 接入页面不会自动下载仓库或安装工具链。

### 2. 在 Web 创建节点凭据

1. 打开“执行节点”。
2. 在“注册新节点”中填写一个容易识别的名称，例如“Linux 构建机 01”。
3. 点击“创建节点凭据”。
4. 保存页面展示的“节点 ID”和“Token”，然后点击“已保存，关闭凭据”。

Token 相当于这个节点的连接钥匙，只展示一次。把它交给维护该节点的人，配置到环境变量或 DSH 凭据服务；不要填写到业务代码中。

### 3. 在机器上配置 DSH 节点

节点管理员需要配置中央地址、节点 ID、凭据引用和工作副本，并重启 DSH。配置文件位置与完整示例见[节点配置](central-deployment.md#3-创建并配置节点)。

配置生效后，回到“执行节点”，确认该节点已经**在线**，并显示了预期的工作副本。每个 DSH 实例使用自己独立的节点凭据。

审核身份由管理员在创建账号时设置为 `reviewIdentity`，并与候选 owner 对应。它不一定等于登录名；本地插件设置中的 owner 不能切换中央登录身份。

### 4. 接入项目

1. 进入“项目管理”，点击“＋ 接入项目”。
2. 填写项目名称。
3. 选择在线、兼容的执行节点，再选择它上报的工作副本。
4. 点击“确认接入”，等待首次同步。

例如，“服务器核心库”项目可以绑定“Linux 构建机 01”上的 `server-core` 工作副本。

接入时主要选择已经准备好的工作副本。仓库目录、目标分支、模型执行方式和工具链由节点配置决定，不能在这个表单中随意切换。

### 5. 发起第一次全量审查

1. 打开项目卡片。
2. 在“本次审查补充说明”中填写关注点，也可以留空。
3. 点击“开始全量审查”。
4. 在“任务记录”查看进度，结束后到“审查报告”和“候选队列”查看同步结果。

补充说明可以这样写：

> 重点关注网络重连和超时处理，保留现有协议兼容性；涉及行为变化的地方请明确列出人工判断项。

中央“审查报告”目前用于阅读报告和 findings，没有“转换 finding”或“忽略 finding”按钮。报告中有待人工判断或前置依赖，不表示已经产生可批准的修复候选。

### 6. 配置定时审查

在中央工作台打开项目详情，找到“定时审查”，填写每日计划开始时间和时区，勾选启用后保存。节点在计划时刻有空位时可以立即受理，繁忙或暂时离线最多等待 30 分钟。手动任务优先，等待期结束时尚未受理的本轮会跳过，已受理的审查继续执行并收尾。

执行节点需使用支持定时审查的插件、进程型 Runner 和完整检出的工作副本。SVN 节点使用客户端附带的 `svnversion` 核验检出范围。稀疏检出、切换过子路径的 SVN 工作副本，或业务文件和 `.ai-review/` 有本地变动时，本轮跳过并保留现场，任务记录会显示原因。节点同步项目绑定的目标后，先按当前代码复查上轮结果，再做全仓扫描。项目详情显示下一次计划与最近状态。旧本地间隔设置已移除，请在中央逐项目启用。

## 提出意见与再次修复

### 写总体意见

打开候选的“审核意见”，在“新增审核意见”中描述问题，点击“提交意见”。建议写清**触发条件、当前问题和期望结果**。

例如：

> 断线后连续重试失败时，当前逻辑仍会发送请求。请在达到重试上限后停止发送，并补充达到上限时的验证。

点击后会留在候选页等待节点回报，也可以从导航打开“任务记录”。确认意见提交成功并等待候选同步后，再发起修复。**意见会写入仓库并同步远端**；浏览器里尚未提交的文字只是草稿。

### 对具体代码行提意见

1. 打开“代码差异”。
2. 点击需要讨论的代码行，页面会切换到意见输入区，并带上文件和行号。
3. 填写意见，检查定位后提交。不需要定位时，点击“移除定位”。

查看“当前完整补丁”时，两侧都可以定位。查看两个版本之间的增量比较时，当前仅支持在**右侧的当前版本**上添加定位意见。

### 让 AI 按意见修复

1. 先提交需要处理的意见，并等待提交任务完成。
2. 回到候选详情，点击“让 AI 处理未解决意见”。
3. 到“任务记录”查看修复结果。
4. 如果生成了新版本，重新打开候选，比较新旧差异并重新审核。

提交意见不会自动启动 AI 修复，两步需要分别操作。修复成功也不等于已经批准业务代码，新版本仍需人工审核。

如果任务显示“需要人工处理”，说明节点使用提示词模式，未自动调用模型。可以请节点管理员配置自动执行的 AI Runner，再从候选详情发起修复。若修改需要人工完成，请直接按目标仓库的开发和提交流程处理。

### 意见状态与候选状态

确认某条意见已经处理后，可以点击“标记已解决”。这个按钮记录意见处理情况，不会替你修改代码。

如果候选处于“待修复”，且你确认当前版本已经可以继续审核，可以点击“恢复为待审核”。恢复状态不会替代代码修复，之后批准时仍会重新检查。

## 草稿、版本变化和拒绝

### 草稿如何保存

评论草稿按账号、项目和候选区分，保存在当前浏览器标签页中，刷新页面后可以继续编辑。关闭标签页、清理浏览器数据或更换浏览器后，草稿可能无法保留；需要共享的意见应正式提交。

如果编辑时出现“版本已更新，草稿保留”：

1. 阅读当前版本的新代码和意见。
2. 修改草稿，使它对应当前版本。
3. 点击“已核对，应用到当前版本”。原有行定位会移除，需要时重新选择代码行。
4. 再提交意见。

版本变化后，人工判断也需要针对新版本重新确认。

### 不接受这份修复

在“处理原因”中写清原因，点击“拒绝候选”并确认。候选会归档为“已拒绝”，相关记录保留在仓库中。

以后需要重新处理同一个问题时，应先产生一份新的候选。在新候选的“关联被拒来源”中填写旧候选编号，例如 `2026-11/fix-timeout`，填写处理原因，再点击“记录重新打开的来源”。这会记录新旧候选的关系，旧候选仍保留原来的拒绝记录。

## 读懂任务结果

一条任务有三层信息，需要一起看：

| 信息 | 回答的问题 | 常见显示 |
| --- | --- | --- |
| 执行状态 | 这次操作进行到哪一步？ | 排队中、已受理、执行中、已结束、待核验。 |
| 业务结果 | 审查、修复或批准实际得到了什么结果？ | 已提交、已中止、校验未通过、需要人工处理。 |
| 交付状态 | 相关提交是否已经到达远端仓库？ | 已交付远端、待交付远端、交付冲突、结果待核验、无需交付。 |

例如：

- **已结束 + 已提交 + 已交付远端**：提交已经存在，远端也已确认收到。对于批准任务，表示本次批准交付完成。
- **待核验 + 已提交 + 待交付远端**：业务结果已证明提交存在，但远端交付未完成。应核验并交付原提交，不要重新执行批准。
- **已结束 + 需要人工处理 + 无需交付**：通常是生成了人工操作提示，这次没有需要交付的提交。

从支持人工补丁提交的版本升级时，请同时更新中央和执行节点。若旧节点保留了中央尚未确认的人工补丁受理记录，更新节点后会自动结清。

批准任务如果出现 `FALLBACK_TO_PENDING`，表示**本次没有批准成功**。补丁冲突或门禁失败后，系统可能生成了新的修复版本，需要回到候选继续审核。即使交付状态显示已交付，也要确认它交付的是修复版本还是批准结果。

排查任务时，先看结果说明，再看“执行日志”；需要完整信息时展开“完整业务结果”。向管理员反馈问题时，可以提供项目名称、候选编号、任务编号和错误说明。

## 常见问题

### 按钮为什么是灰色的？

按下面顺序检查：

1. 项目是否启用，节点是否在线，项目是否显示“已同步”。
2. 项目是否已有正在执行或待核验的任务。
3. 你是否是候选负责人；需要接管时先确认分工。
4. 候选是否处于允许该操作的状态，例如只有“待审核”才能批准。
5. 人工判断是否确认完整，候选是否存在校验错误。
6. 批准弹窗中是否已明确同意执行门禁命令。

“让 AI 处理未解决意见”还要求至少存在一条未解决意见。

节点执行审查或修复期间，同项目不能再创建其他写任务。可以继续查看中央已有缓存，但新的详情读取可能等待安全窗口。网络读取超时不表示原业务操作未执行。

### 节点在线，为什么还显示未同步或同步延迟？

在线表示节点仍在连接中央服务，不代表项目数据已经更新。先查看“上次同步”时间并稍等页面自动更新；长时间不变时，请管理员查看节点状态和日志。

节点离线时，已经同步、缓存过的内容仍可能可读；尚未读取过的详情可能暂时无法打开。

### 提示仓库版本已变化，怎么办？

点击候选页的“刷新详情”，重新核对代码和当前版本。如果是工作副本尚未跟上仓库更新，可以在项目详情中执行“同步仓库”，等待完成后再操作。

“业务基线变化”表示仓库中的业务代码已经与生成补丁时不同。可以使用“重新基于最新代码生成补丁”，然后重新审阅结果。

### 任务卡住了，可以直接再点一次吗？

先打开对应任务看状态。同一个项目有未决任务时，新写操作会被阻止。不要通过重复批准、重启服务或删除运行记录来跳过它。

需要停止正在执行的任务时，点击“请求取消”。页面显示“已请求取消，等待节点回报”后，继续等待节点确认最终结果。取消请求不能撤回已经完成的远端提交。

### 已经提交，为什么没有交付成功？

Git 可能已经产生本地提交，但因为网络、凭据或远端分支冲突没有推送成功；SVN 也可能遇到提交结果无法确认的情况。

请管理员先核对远端、工作副本和原提交。任务处于“待核验”时，**确认旧执行进程已经停止**，再勾选“我已确认旧执行进程停止”，点击“核验并重试原提交交付”。

恢复操作核验已有执行与提交，不重新批准或重跑业务。无法证明结果时，任务会继续保留为待核验；详细处理见[部署说明中的恢复章节](central-deployment.md#5-停止备份和恢复)。

### 可以修改项目绑定或停用项目吗？

项目详情可以修改名称、启用或停用项目。存在未决任务时，配置修改会被拒绝，应先处理任务。

当前 Web 不支持直接迁移节点、切换工作副本或目标分支。需要调整时，由管理员处理，参照[部署说明](central-deployment.md)。

### 如何让一台机器停止接入？

由管理员先处理未决任务，确认执行已停止，再在“执行节点”中吊销凭据。吊销后，该凭据无法继续连接中央服务；它不能代替终止机器上已经运行的进程。

## 当前版本的使用边界

目前支持手动及定时全量审查、多节点和多项目管理，以及查看、评论、修复、人工批准和 Git/SVN 远端交付。以下能力尚未提供：

- 细粒度项目权限和角色管理。
- Web 自动 clone/checkout、安装工具链、在线迁移项目绑定或自动切换故障节点。

中央模式的共享写入会尝试交付远端；本地 Git 模式只做本地提交，操作方式见[本地插件指南](dsh-code-review-guide.md)。实际 DSH 宿主、模型服务和项目工具链须在部署环境验证，已验证范围见[拆包验证记录](package-boundaries-validation.md)。
