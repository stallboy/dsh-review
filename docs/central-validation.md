## 2. 自动验证

环境为 Windows、Node.js 24.15.0。使用实际 Git 和 SVN 临时仓库，没有把 VCS 提交替换为成功桩。

```text
npm run typecheck
npm run build
node --test --test-concurrency=1 --test-reporter=tap tests/*.test.mjs
```

测试设置 `DSH_HOME=<当前工作区>/.tmp/final-test-home`，避免读取或改写真实 DSH 配置。SVN 临时仓库及进程终止夹具在普通沙箱中受权限限制，最终完整验证使用允许这些本机测试操作的执行环境。最终全量测试耗时约 270 秒。

## 3. 浏览器验证

使用本机真实 HTTP 中央服务、两个独立节点、两个 Git 工作副本及各自的本地裸远端。数据均为隔离夹具，不连接团队业务仓库。

- 登录后工作台显示两个项目及对应节点同步状态；按项目筛选仅保留该项目候选。
- 候选详情可查看方案、完整补丁的并排差异、审核意见及版本/门禁。
- 批准弹窗完整显示门禁命令；没有明确同意执行时提交按钮禁用，同意后可提交。
- 一项候选已走通门禁、原子提交与 Git 推送；任务页分别显示“已提交”“已交付远端”，最终日志包含提交版本及业务结果。
- 另一项目的评论由登录身份写入并交付，候选同步为待修复；后续草稿刷新后仍保留。
- manual Runner 的 AI 修复入口返回 `MANUAL_REQUIRED`，任务页显示人工提示入口，没有声称调用真实模型。
- 检查 390px 窄屏布局，随后恢复 viewport；最终注销复测立即返回登录页。

临时浏览器服务已停止，两个 Git 工作副本与临时中央数据库已清理。原型页面是讨论资产，正式产品读取中央 API，不内置这些夹具数据。
