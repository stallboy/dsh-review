# 人工接手后的修复核验计划

> **任务来源**: 在审查流程设计讨论中，用户确认将「提交修复线索」列为可选计划，并提出由下一轮审查主动核验和补记修复提交。
> **任务内容**: 定义人工接手项的跨轮核验、修复归因和可选人工线索。
> **参考文档**:
> - `SPEC.md` §4.8 — 发现标识、有效观察与跨轮状态投影
> - `SPEC.md` §16.11 — 中央定时审查的历史复查与证据要求
> - 本次对话 — 接受并应用、本次不修改、人工接手三个审核动作及外部 Agent 交接流程
> **生成日期**: 2026-11-20

## 默认流程

1. 审核者选择「人工接手」后，决定与交接内容按稳定的 `finding_id` 保留，并进入下轮复查清单。无需填写 PR、提交号或验证结果。
2. 下一轮审查在覆盖相关范围、能读取有效基线时，按原问题的复现条件与验收标准核对当前代码。人工提供的线索可帮助定位，缺少线索仍照常复查。
3. 确认问题已解决后，审查工具再根据相关代码差异、提交历史及可用验证证据判断哪些提交解决了问题。证据能支持归因时，在本轮复查记录中补记一个或多个提交，并简述依据。人工线索保留原样，便于追溯。

## 结果判定

| 复查结果 | 记录方式 |
| --- | --- |
| 已确认解决，且能定位修复提交 | 关闭发现，记录解决证据和修复提交。 |
| 已确认解决，但无法可靠归因 | 关闭发现，记录解决证据，修复提交留空。 |
| 问题仍存在、证据不足，或审查范围未覆盖 | 保留人工接手状态。有核验结果时记录证据或缺口，等待后续复查。 |

## 可选入口

在「人工接手」的详情中提供「提交修复线索」，允许填写 PR、提交号或验证说明。提交线索仅补充复查输入。是否关闭发现由复查证据决定。

## 实施顺序与验收

1. **接入历史复查**。验证无需人工线索也能按 `finding_id` 找到并复查接手项，未覆盖或证据不足时保留原状态。
2. **补记修复提交**。验证可归因时能记录单个或多个提交，已解决但归因不明时仍可关闭，提交字段保持空白。
3. **提供可选线索入口**。验证提供线索能辅助定位，错误或无关线索不会导致误关闭。
