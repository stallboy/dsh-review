## 审查来源与范围

本轮审查确认了两个 P1（失效 PID 锁回收竞争、已停用工作副本阻断所有项目恢复）及两个 P2（旧托管配置失去中央入口、不同端口网关 Cookie 冲突）。原验证记录的“无未决”是当时审查结论，不替代本次后续发现。本轮在原隔离 worktree 的 `codex/embedded-central` 分支修复，不推送或合并。

## 修复与回归

- 配置所有权改用 SQLite 排他事务。原先的两个并发实例均取得锁已先复现失败；新回归同时检查活动进程互斥及异常退出自动释放。
- 停用项目保留声明及历史，目录缺失不再阻断其他项目。新增真实 A/B 工作副本回归已先复现 `ENOENT` 与故障状态无法停用的问题；修复仍保留中央 Web 重新启用后无需重启插件的原能力。
- 故障项目停用前继续检查本地执行记录、中央未决指令及旧实例租约；不能将“受理暂停”当成旧执行器已经停止。控制面状态接口仅补充自身实例标识和活动状态。
- 旧托管模式保留已有中央安全外链，禁止直接覆盖及本地写入的约束保留。新增真实 bundle VM 回归已先确认旧入口消失，再修复中央页与本地指引。
- Cookie 读取/写入统一使用实例命名空间哈希。真实中央及双网关共享按名称/路径存储的 Cookie jar，先复现 A 登录被 B 覆盖，再验证两个不同账号跨端口往返均保留会话。

独立复核另确认一个修复收尾问题：断开旧实例请求失败可能遗留 `starting`。已先用真实 HTTP 注入响应丢失复现，再将整段状态转换纳入统一错误处理；失败进入 `error`，再次停用可安全恢复 `ready`。独立最终复核已重跑内存故障注入确认闭环，当前无未决 P0/P1/P2。
