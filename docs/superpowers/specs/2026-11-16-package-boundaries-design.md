# 单仓多包边界整理设计

> **任务来源**: 用户询问插件与中央管理服务是否应拆分，认可“保留单仓、划清包边界与交付产物”的建议并授权实施。
> **任务内容**: 将 DSH 插件迁入独立 workspace，共享浏览器可用的数据契约，分别交付插件和中央服务，保留原审核行为。
> **参考文档**:
> - `SPEC.md` — 审核不变量、DSH 集成及中央模式权威契约。
> - `AGENTS.md` — worktree、测试与独立审查约定。
> - `docs/superpowers/specs/2026-11-16-central-review-web-design.md` — 中央服务与执行节点职责。
> - `docs/central-deployment.md` — 现有部署方式。
> **生成日期**: 2026-11-16

## 已认可的选择

保留单仓并整理 npm workspaces。维持现状会继续混合插件与全仓入口；拆成多个 Git 仓库会增加尚无需求支撑的协议发布与跨仓协调成本。本次不提取独立评审核心包，不修改审核、身份、锁、持久化、交付或恢复语义。

## 包与依赖

- `packages/dsh-plugin`：插件元数据、资源和源码。保留 `src/host` 的审核能力，中央节点适配移到 `src/managed`，DSH 界面在 `src/client`。插件标识、导出入口和 HTTP 路径不变。
- `packages/protocol`：节点通信契约及 Web 使用的候选、评论、队列等纯数据类型。插件内部设置、执行器与异常继续留在插件内。
- `apps/server`：中央服务，依赖 protocol，不导入插件。
- `apps/web`：中央工作台，只依赖公开契约，不跨包导入插件源码。
- 根包只管理工作区、统一构建、测试和打包；根 `tests` 保留现有契约与跨组件验证。

## 交付

插件独立生成安装 tarball，包含 DSH 入口、资源、托管节点实现及必要协议依赖，不包含中央服务或中央 Web。中央服务 tarball 包含运行依赖及已构建 Web；静态目录相对自身安装位置解析。两个 tarball 均须在独立临时目录离线安装后验证，不能依赖源码目录的 workspace 链接。

## 验证与风险

先记录现有 typecheck、build 和全量测试基线。迁移只修改现有测试的模块/资源定位，不删除用例或放宽断言；新增包边界和隔离安装回归。重点核验插件资源的相对位置、托管模块导入、共享类型字段、静态文件定位和 bundledDependencies。完成后执行全量验证及独立审查，复核成立的问题后修复。仅提交任务分支，不推送、不合并主副本。
