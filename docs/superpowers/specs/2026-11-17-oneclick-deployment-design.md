# 三平台一键部署与启动设计

> **任务来源**: 用户要求 Windows、Linux、macOS 的一键部署和一键启动脚本，覆盖中央与 DSH 节点，并要求审查和测试；随后明确部署/启动必须分开，部署可重复覆盖，`--git` 先获取最新代码，Node.js 24 不满足时退出。
> **任务内容**: 提供独立部署与启动入口，安全替换程序、保留数据配置，支持源码更新及安装包部署，并验证实际行为。

> - `../../central-deployment.md` — 当前部署方式及已知限制。

> - `../../../apps/server/src/cli.ts` — 中央启动及账号初始化。
> - `../../../packages/dsh-plugin/src/managed/managed-config.ts` — 节点配置与凭据解析。

## 已确认范围与选择

覆盖中央服务和 DSH 节点。采用两个独立 Node.js 脚本实现部署和启动，Windows `.cmd`、Linux `.sh`、macOS `.command` 只转发参数。共用实现避免三套覆盖/保留逻辑漂移；不改用容器，不自动安装 Node、DSH、TLS 或系统服务。

用户的新说明作为前一轮方案的细化直接执行，不重复要求确认。默认使用当前源码；`--git` 在临时目录克隆远端最新目标分支后构建，不能把正在部署的工作目录当成 Git 更新目标。支持显式安装包以便离线部署。

## 操作与数据

- `deploy.* --role central|node --target <目录>`：检查 Node >=24，构建/安装到临时区，成功后替换 `<target>/app`，更新启动文件与无密钥配置。程序可覆盖，数据不在 app 内。
- `--git`：默认仓库 `https://github.com/stallboy/dsh-review.git`、分支 `master`；允许 `--repository`、`--branch` 指定实际来源，用本地 Git 夹具验证更新行为。
- `--package <tgz>`：使用自带运行依赖的安装包离线安装，与 `--git` 互斥。
- `start.* --target <目录>`：只读取部署配置并启动，不构建、不安装、不拉取 Git。部署目标本身附带启动脚本，脱离源码仓库也可启动。
- 中央：保留数据目录；没有账号时用密码环境变量或交互输入初始化。已有账号不重建、不改密码。监听地址、端口、公开 URL 可在部署时设置。
- 节点：安装插件，保留既有 workspaces 与 managed 执行记录；首次提供中央地址、节点 ID、工作副本及 DSH 启动程序。配置仅记录 tokenReference，不保存 Token。启动将 DSH_HOME 和现有凭据环境传给 DSH。
- DSH 首次启用仍由插件管理器完成，脚本输出准确安装路径；不能伪造已启用或节点在线。Windows 使用原生可执行文件或 Node.js CLI 入口启动 DSH，不把用户参数拼接成 shell 命令。

## 失败与覆盖约束

安装/构建失败时旧 app 和配置保持可用。替换过程使用同目标目录的暂存与旧版本回退；部署进程互斥，脚本启动的进程未停止时拒绝覆盖。不自动终止其他进程。数据目录不能与被替换程序目录重叠，拒绝将源码仓库或磁盘根目录作为部署目标。Token 和密码不写日志、启动参数或业务仓库。

## 验证

测试覆盖首次部署、反复覆盖并清理旧程序、数据/配置/账号保留、安装失败保留旧版、真实 Git 更新、启动不部署、空格和特殊字符路径、节点配置与环境传递、并发/运行占用、Node 版本与失败退出。Windows 实测原生入口；POSIX 入口用可用 Bash 执行，并增加三平台 CI 矩阵。没有真实 Linux/macOS 执行证据时明确记录未验收，不把 Windows 上的 Bash 当作原生验收。
