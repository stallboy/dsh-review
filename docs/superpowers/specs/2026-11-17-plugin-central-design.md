# 插件中央连接与项目接入设计

> **任务来源**: 用户要求同一机器、同一 DSH 内的少量项目可以通过插件启动中央服务，在插件内完成评审；讨论后确认手动选择项目、支持已有中央地址，并授权补充文档后实施。
> **任务内容**: 实现实例级中央连接管理、本机中央进程生命周期、按工作副本选择纳管，以及同源内嵌中央工作台。

## 1. 已确认的产品行为

- 一个 DSH 实例共用一个当前中央连接、一个节点和多个独立工作副本。会话用于定位项目，同一工作副本的多个会话复用接入记录，不同项目均可纳入。
- 插件提供“中央连接”“项目接入”“中央工作台”，管理设置归属 DSH 实例，不随会话切换。
- 中央连接支持“本机托管”和“连接已有中央”。已有中央可以在本机或其他机器长期运行；插件不控制其进程。
- 选中或编辑本机托管配置不启动进程。用户点击“应用并启动”后保存并启用；后续插件启动自动恢复已启用连接。
- 打开、关闭页面或切换会话不影响中央生命周期；接入项目复用现有进程；没有项目时也能启动中央。
- 插件停止时停止其自行拉起的中央进程。插件重载按停止再启动处理。手动停止会停用连接并保留设置，下次插件启动不自动恢复，直到再次启用。
- 自动发现项目候选，用户选择接入，后续自动注册、重连和同步；发现或接入项目不自动开始审查。
- 当前会话提供所属项目的快捷入口，工作台同时允许访问全部已接入项目。
- 相同真实目录去重；不同工作副本即使远端相同也分别管理。关闭会话不删除接入记录和历史。
- 存在未决业务写指令或未核验的本地执行记录时，禁止切换中央、停用连接、改动项目接入配置。插件被停止时仍必须释放其进程，执行中断按既有恢复契约处理。

## 2. 方案取舍

| 方案 | 取舍 | 决定 |
| --- | --- | --- |
| 插件拉起独立中央子进程 | 复用中央发行物，增加进程与就绪管理 | 采用 |
| 将中央运行在插件进程中 | 进程较少，中央故障与宿主耦合 | 不采用 |
| 注册系统服务 | 适合独立长期运行，增加部署负担 | 通过“连接已有中央”使用，不由插件安装 |

拉起时机比较：配置选中即启动容易误触；首次打开工作台才启动会使节点接入依赖页面。因此采用“显式启用后启动，后续随插件恢复”。

## 3. 职责与交付

中央继续管理账号、项目、指令与查询视图；持有工作副本的插件节点执行 Agent、门禁及 VCS 操作。插件增加连接控制器、中央子进程监督器、同源工作台网关。中央不导入插件。

保留轻量插件与独立中央包，增加可直接安装的本机整合插件包，内含独立中央运行目录与 Web。运行时不执行 npm 安装、构建或 Git 更新。需要 Node.js 24 或更新的宿主运行时，启动 Electron 宿主的子进程时按 Node 模式运行。

## 4. 配置、身份与状态

配置保存在 DSH_HOME 下插件独立目录，不写业务仓库。连接分为已保存配置与当前运行状态，UI 读取配置不产生启动副作用。连接变更串行处理，进程启动具有单实例保护。

独立复核后收紧：所有配置写入和启动恢复都先取得实例锁、重读最新配置与秘密，再决定是否启用。切换过程中保持配置所有权，防止第二个实例覆盖凭据或撤销用户刚完成的停用。

实施选择：同一 DSH 首期一个当前中央；按中央持久身份隔离节点执行日志、节点凭据和项目映射。中央公开只读信息端点返回持久中央 ID 与协议版本；地址变化后核验 ID。新中央要求重新授权，不复用旧中央的节点身份、执行日志或项目绑定。切换不迁移、删除原中央数据。

本机托管使用私有 IPC 引导首次账号和节点凭据，审核身份由用户首次填写。已有中央使用管理员预置的节点 ID 与 Token。用户浏览工作台仍遵守中央用户会话与 CSRF 校验；节点凭据不能代替审核用户。秘密保存在受限的插件私有文件，普通设置和状态不返回 Token 或密码；该选择兼容目前仅提供解析 API 的 DSH 凭据服务，不要求修改宿主。

服务、节点和项目分别显示就绪状态。失败保留已保存设置和可诊断错误，提供显式重试；节点临时失联继续使用原协议重连，不自动切换中央、不自动重跑业务。首期中央进程异常退出显示故障，由用户重试，避免崩溃循环。

## 5. 项目发现与接入

候选来自宿主工作区列表与当前会话 cwd，解析 Git/SVN 工作副本根并规范化真实路径。无有效工作副本、目标分支不明或工具不可用时展示失败原因，不猜测目标。多个会话映射同一真实目录时合并候选；同名不同目录分别展示。

用户接入前核对名称、目录、VCS 与目标；后台保存稳定 workspaceId、注册节点允许执行的工作副本，并幂等建立中央项目绑定。节点仅能管理自身已声明 workspace 的接入，不能修改其他节点。停用保留中央项目及历史，不删除目录。接入重试和插件重启复用原 ID。项目接入变化在没有未决写操作时生效。

实施时采用“原子暂停新指令 → 停止旧节点 → 暂停注册新实例 → 幂等恢复项目 → 显式激活”的握手，接入变化不重启中央进程。同一实例的续注册保留中央当前暂停状态，实例租约不与受理状态混用。恢复已有绑定保留中央 Web 修改的名称和启停状态；只有用户显式操作的项目才修改启停状态。

## 6. 内嵌访问

插件使用固定同源路径承载 iframe，代理到当前已保存并核验身份的中央。网关仅开放中央 Web、静态资源及用户 API，禁止节点 API；不支持通过请求参数指定代理目标。前端资源、Router 和 API 统一使用可配置的基础路径。

每个浏览器网关会话独立保存中央 Cookie，不转发 DSH Cookie、Authorization 或节点 Token；中央切换时清空网关会话。保留中央 CSRF 校验、同源框架限制及内容安全策略。中央登录产生的 Cookie 不直接覆盖 DSH Cookie。本机模式可经内部引导为网关建立明确本地操作者的会话；已有中央展示中央登录页。

插件管理写接口需要当前插件控制令牌；令牌不进入 URL。项目发现仅查询本机宿主已知目录，不接受浏览器提供任意路径。

网关用连接代数拒绝切换前的迟到登录/响应。本机退出登录会移除映射，后续重新进入时重新引导；会话过期仅允许重新建立会话并重试会话读取，不自动重放业务写请求。已有中央仍使用其正常登录流程。

## 7. 生命周期及恢复

启动子进程后等待私有 IPC 就绪，只有收到实际监听地址、中央身份及必要凭据后才显示就绪。中央仅监听回环动态端口。启动超时或失败只终止自身子进程；父进程断开 IPC 时子进程退出，防止宿主异常退出留下孤儿。

停止顺序为阻止新配置操作、停止节点并保存/回报执行记录、停止自身中央进程、关闭网关。插件强制停止无法证明业务未提交，必须保持恢复所需持久记录，不自动回滚或重跑。

旧 managed-node.json 继续按原方式运行。实施选择：检测到旧配置时，插件显示迁入诊断并从服务端拒绝直接覆盖；须先处理旧中央任务，停用旧托管配置并重启，再使用新连接管理。旧执行记录不得删除或自动改挂到新中央。

原本地会话评审入口继续保留；一旦保存中央连接，连接故障或手动停止也不会重新开放原本地写入口，避免绕过托管归属与未决任务。

## 8. 验收

- 首次编辑不启动、应用后启动、零项目启动、后续恢复、手动停用不恢复、插件停止和父进程消失后无中央遗留。
- 已有中央地址校验、凭据错误、协议不兼容、中央身份变化、未决任务切换阻止；停止插件不停止已有中央。
- 多项目多会话发现、真实目录去重、项目接入重试无重复、停用保留历史、关闭会话不取消纳管。
- 通过真实 HTTP 网关完成登录与 CSRF 写入，验证子路径页面/资源/API、Cookie 隔离、节点接口阻止及代理目标固定。
- 本机整合安装包脱离源码目录启动，轻量插件与独立中央交付继续通过。
- 执行 typecheck、build、全量测试并独立审查。真实 DSH 宿主 UI 与三平台运行证据分别记录，不将测试替身等同真实宿主验收。
